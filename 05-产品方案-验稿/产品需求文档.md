## 0. 立项依据（这个产品从哪来）

我做过一个运维排障系统 **FaultDetect**。它的内核不是"排障"，而是 **"我怎么让一个自动结论变得可信"**：
每条假设都带 **反证条件 + 验证动作**；有**独立真值的自检**（真值走一套实现、被测走另一套）；有**"已知边界"专章**如实标注判不准的地方；外部调用异常**一律降级，绝不落"成功产物"**。

我把这套内核**从运维里抽出来**，换到一个所有用 AI 工作的人都会遇到的场景：

> **我有一份 AI 写的东西，我要交出去，但我不敢信它。**

**触发这个产品的真实事件**：我自己用 AI 生成了一份面试答题，交付前发现三类问题 ——
1. 引用的数据我无法溯源；
2. 通篇语气笃定，但有多处其实是推断；
3. 与我自己简历的口径不一致。

**这三个问题，没有一个通用工具会主动告诉我。** 这就是验稿要解决的事。

---

## 1. 核心承诺

验稿是一个**本地优先**的工具（桌面应用 / 本地 Web）。它不帮你写得更快，也不评价文笔。
它只回答一个问题：

> **这份稿子里，哪些话站得住，哪些站不住。**

**导入稿件 → 抽取全部事实断言 → 逐条判定溯源状态 → 标出"其实不确定却说得极肯定"的地方 → 与用户的事实底稿对账 → 输出一份可复核的可信度报告。**

首要成功标准**不是功能数量**，而是：
- 新用户在 **3 分钟内**跑完第一份稿子；
- 在**没有预置数据、假指标、演示样例**的情况下，从真实文件开始；
- 每一条判定都能**点开看到依据**；判不出来的一律标"待确认"，**不猜**；
- 报告里**必须**包含"我不确定的地方"，而不是只给一个数字；
- 失败时告诉用户**哪里失败、为什么、现在要点什么**。

---

## 2. 用户与使用原则

### 2.1 目标用户

首版用户就是我自己：**需要用 AI 加速产出，但产出的东西要交给人看、要经得起追问的人**（实施 / 交付 / 售前 / 内容 / 求职）。

### 2.2 人类直觉原则

1. **入口按任务而非按技术划分**：首页只有「验一份稿」「我的事实底稿」「历史报告」三个入口。
2. **渐进披露**：规则、阈值、模型参数全部默认隐藏。
3. **草稿与提交分离**：所有判定先落「待确认」，人工确认后才进入正式报告。
4. **可见的真实状态**：没有稿件就是空状态；没有事实底稿就**明说**"本次无法对账，只做内部一致性检查"。
5. **解释而非猜测**：每个标记都能点回原文那一句。
6. **永不丢失上下文**：随时可中断，重开继续。
7. **用户掌控**：可暂停、可推翻任何一条判定；**推翻必须记录理由**。

## 3. 首次使用（唯一主路径）

1. 粘贴 / 导入一份稿子（md / txt / docx）
2. 系统给出「事实断言清单」，逐条标注：可溯源 / 与底稿冲突 / 无法溯源 / 待确认
3. 用户逐条确认或推翻 → 生成《可信度报告》

---

## 4. 核心功能

### 4.1 断言抽取

把稿件切成**可判定的事实断言**（不是切句子）。每条带：`id`、原文位置、断言内容、类型（**事实 / 推断 / 观点**）。
**类型判定必须给出依据**，不允许只给一个标签。

### 4.2 三态溯源判定（继承 FaultDetect 的可解释性）

每条断言**必须同时给出三样**，缺一不可：

| 要素 | 含义 |
|---|---|
| **依据** | 命中了哪个事实源、哪一段原文 |
| **反证条件** | 什么情况下这条判定会被推翻 |
| **验证动作** | 用户可以去哪里、怎么自己核一遍 |

**只给这三样，不给"我认为"。**

### 4.3 语气-证据错配检测（本产品独有的价值点）

找出**"证据强度低、但语气极肯定"**的句子：出现"必须 / 一定 / 所有 / 唯一 / 完全 / 必然"等绝对词，但判定类型是**推断**。
**这类句子是交付物被追问时最先崩的地方。**

### 4.4 事实底稿对账

用户维护一份自己的「事实底稿」（经历、数据、结论、口径）。
稿件与底稿冲突时高亮，并**并排列出冲突双方原文**。

### 4.5 行级红绿 Diff

用户改稿后，给出"AI 改了什么 / 你改了什么"的行级差异，让改动**看得见**。

### 4.6 可信度报告（可交付物）

- **顶部**：一句话结论（可溯源 N 条 / 冲突 N 条 / 无法溯源 N 条 / 语气错配 N 条）
- **主体**：逐条断言 + 三态判定 + 依据可点开
- **末尾**：**「本次我判不了的」**章节（明确列出系统自己不确定的部分）
- **显式声明**：本报告不判定对错，只判定"能否溯源"

---

## 5. 安全与边界

- **绝不用生成方自己审自己**：审计证据必须来自**独立来源**（用户底稿 / 用户提供的原件 / 用户确认），**不接受"让同一个模型再读一遍自己的输出"作为依据**。
- 不替用户下"对 / 错"的结论，只给"可溯源 / 不可溯源 / 冲突"。
- **不自动修改稿件内容**，只标记。
- 判不出来一律「待确认」，**不允许为了让报告好看而猜一个状态**。
- 原件与底稿默认**仅存本机**；密钥不入库、不进日志、不进导出包。
- 外部调用失败（超时 / 限流 / 非法响应）一律**降级为"规则判定 + 待确认"**，绝不产出假成功。

---

## 6. 首版范围与明确不做

**首版必须完成：**
1. 导入 md / txt / docx
2. 断言抽取 + 类型判定（含判定依据）
3. 三态溯源判定（依据 / 反证条件 / 验证动作）
4. 语气-证据错配检测
5. 事实底稿 CRUD 与冲突高亮
6. 行级红绿 Diff
7. 报告可导出
8. 全过程可中断、可恢复

**首版明确不做：**
- ❌ 不做"AI 帮你重写 / 润色" —— 那是另一个赛道，会稀释定位
- ❌ 不做联网自动查证 —— 首版只对"用户底稿 + 用户提供的原件"对账
- ❌ **不做分数化的"可信度打分"** —— 一个总分是最容易被误读的东西，只给计数与清单
- ❌ 不做团队协作 / 账号体系
- ❌ 不做自动提交 / 自动发送
- ❌ 不要求用户先配置任何模型参数才能启动

---

## 7. 交付验收（以用户任务为单位，必须可判定）

- 干净环境安装后可直接打开；失败可自愈并给出修复按钮；
- 仅凭"一份稿子"就能完成第一份报告（无底稿时**降级为内部一致性检查并明说**）；
- 报告里每一条判定都能**点回原文**；
- 报告里**必须存在**"本次我判不了的"章节，**为空时显示"无"，不允许整章消失**；
- 没有稿子时所有指标**显示空状态**，不出现任何种子数据；
- 中断应用后重启，从上次可恢复节点继续；
- 外部模型不可用时，**全流程仍能产出报告**（降级为规则判定 + 待确认）。
