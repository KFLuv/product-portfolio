## 这是什么阶段的项目

**这是「产品方案」，不是「项目」。** 我在作品集里把它单独分组，理由：

| 判定标准 | 验稿 |
|---|---|
| 有代码吗 | ❌ 没有 |
| 有原型吗 | ❌ 没有 |
| 有用户吗 | ❌ 没有 |
| **有什么** | ✅ **一份完整 PRD（169 行）** |

> **我把「有代码或原型的」叫做项目，「只有文档的」标成方案** ——
> 不想让它看起来比实际更完整。

---

## 但它体现了一件真实的事

这个方案不是凭空写的，它来自我在另一个项目（FaultDetect）里踩到的坑：

**「看起来成功了」和「真的成功了」是两回事。**

| FaultDetect 里的做法 | 迁移到验稿 |
|---|---|
| 每条判断带**反证条件** | 每条结论要能说清"什么情况下它不成立" |
| 结论分**三层**（观测 / 归因 / 结论） | 同样分三层，且**在界面上长得不一样** |
| 评测口径**从严**（报 7/8 而不是 8/8） | 可信度评分不给单一数字 |

**所以它更像是一份「我在另一个项目里学到的判断，换个场景写成方案」。**
