# 人力招聘归档系统 · 使用指南

> 从零把这套系统跑起来。**三种启动方式，按你的场景选一种。**

---

## 一、三种部署方式对照

| 方式 | 端口 | 适用场景 | 需要什么 |
|---|---|---|---|
| **① 纯 Docker** | 80 / 8082 / 3306 | 演示给别人看、环境干净 | 只需 Docker |
| **② 打包版**（前后端一体） | **8082** | 单机跑起来就能用 | JDK 11 + MySQL |
| **③ 开发模式**（前后端分离） | **8081** 前端 / **8080** 后端 | 改代码 | JDK 11 + Maven + Node.js + MySQL |

```
┌─────────────────────────────────────────────────────┐
│  ① 纯 Docker                                        │
│     浏览器 → :80 (nginx)  → :8082 (后端) → :3306     │
├─────────────────────────────────────────────────────┤
│  ② 打包版                                           │
│     浏览器 → :8082 （后端直接提供前端页面）            │
├─────────────────────────────────────────────────────┤
│  ③ 开发模式                                         │
│     浏览器 → :8081 (Vite) → 代理 → :8080 (后端)      │
└─────────────────────────────────────────────────────┘
```

## 二、通用准备：数据库

**三种方式都需要 MySQL。** 建库并导入表结构：

```bash
mysql -uroot -p < database/init.sql
```

或手动：

```sql
create database if not exists recruitment_db default charset utf8mb4;
```

```bash
# 导入表结构（9 张表）
mysql -uroot -p recruitment_db < database/init.sql

# 如需预算/审批的增量字段
mysql -uroot -p recruitment_db < database/migration_v2_approval.sql
mysql -uroot -p recruitment_db < database/migration_v2_budget.sql
```

**默认连接信息**（见 `backend/src/main/resources/application.yml`）：

```yaml
url: jdbc:mysql://localhost:3306/recruitment_db?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true
username: root
password: <改成你的密码>
```

> ⚠️ **本仓库的密码字段是占位符 `<your-password>`**，跑之前必须改成你自己的。

## 三、方式 ①：纯 Docker（最省事）

```bash
# 一键启动
启动-纯Docker.bat
```

或手动：

```bash
docker compose -f simple-docker-compose.yml up -d
```

**启动后访问**：

| 服务 | 地址 |
|---|---|
| **前端** | http://localhost |
| 后端 API | http://localhost:8082 |
| MySQL | localhost:3306 |

**停止**：

```bash
停止-Docker.bat
# 或
docker compose down
```

**日志排查**：

```bash
docker logs recruitment_backend
docker logs recruitment_frontend
docker logs recruitment_mysql
```

## 四、方式 ②：打包版（单机最快）

**前后端打成一个 jar，后端直接提供前端页面。**

```bash
# 1. 编译打包（需要 JDK 11 + Maven）
编译.bat
# 或
cd backend
mvn -DskipTests package

# 2. 启动
启动后端.bat
# 或
java -jar backend/target/*.jar
```

**看到这行就是成功了**：

```
Tomcat started on 8082
```

**浏览器打开**：http://localhost:8082

> **注意**：`启动后端.bat` 里写的是 `title 招聘系统后端打包版 (8082)`，
> 端口是 **8082**，不是 8080。

---

## 五、方式 ③：开发模式（改代码用）

需要两个终端窗口 + Node.js。

**终端 1 —— 后端（8080）**：

```bash
启动后端-开发模式.bat
# 或
cd backend && mvn spring-boot:run
```

**终端 2 —— 前端（8081）**：

```bash
启动前端.bat
# 或
cd frontend && npm install && npm run dev
```

**浏览器打开**：http://localhost:8081

前端通过 Vite 代理把 `/api` 请求转发到后端 8080（配置见 `frontend/vite.config.js`）。

**改代码后**：前端热更新，不用重启；后端改了 Java 需要重启。

## 六、登录与账号

### 已有账号

`database/init.sql` 末尾有 INSERT 语句创建种子账号。**请查看该文件确认用户名与初始密码**
（不同导入方式可能不同）。

### 自助注册

**登录页可以直接注册**，注册时选账号等级：

| 等级 | 能做什么 |
|---|---|
| **管理员** | 全部操作：创建/编辑/提交/审批/删除 |
| **只读** | **只能查看**，所有写操作被后端强制拦截（403） |

> ⚠️ **已知问题**：`init.sql` 里预置的只读账号，`role` 字段值是 `user`，
> 而只读拦截判断的是 `"readonly"` —— **这个种子账号实际上不会被拦截**。
>
> **要测只读权限，请用登录页的注册功能创建一个新的只读账号。**

## 七、五分钟上手流程

按这个顺序走一遍，能覆盖主要功能：

| # | 操作 | 在哪 |
|---|---|---|
| 1 | 注册一个**管理员**账号 | 登录页 → 去注册 |
| 2 | 看首页统计 | 登录后自动进 Dashboard |
| 3 | **建一个招聘计划**（草稿态） | 计划管理 → 新建 |
| 4 | 填岗位、人数、填报单位 | 计划编辑页 |
| 5 | **提交审批** | 计划列表 → 提交（状态变 `submitting`） |
| 6 | **审批通过或驳回** | 审批管理 |
| 7 | **Excel 批量导入候选人** | 候选人管理 → 导入（模板见 `候选人导入模板.xlsx`） |
| 8 | 候选人**状态流转** | 初筛 → 笔试 → 面试 → 拟录用 |
| 9 | **看操作日志** | 系统日志（你刚才每一步都有记录） |
| 10 | **试三级删除** | 建个草稿计划 → 删除 → 进「已删除」区 → 恢复 / 确认移除 |

### 编制预算拦截怎么验证

在计划提交时，系统会校验**该单位本年度编制人数上限与预算上限**：

- 超限 → **阻断提交**，并给出超了多少的明细
- 想复现：连续提交几个计划把人数配额用满，再提交一个

## 八、常见问题

### `启动后端.bat` 一闪而过

脚本里写死了绝对路径：

```bat
cd /d "E:\Desktop\人力招聘全流程数字化归档管理系统"
```

**改成你自己的项目路径**即可（其他 `.bat` 同理）。

### 8082 端口被占用

```bash
# Windows
netstat -ano | findstr :8082
taskkill /PID <PID> /F
```

或改 `application.yml` 里的 `server.port`。

### 前端报跨域（CORS）

后端 `AuthFilter` 已经把 CORS 头加在所有响应上（`Access-Control-Allow-Credentials: true`）。

如果仍有问题，检查：

- 前端请求是否带了 `withCredentials: true`
- Vite 代理配置是否正确指向 8080

### 登录后提示「请先登录」

**会话依赖 Cookie。** 检查：

- 浏览器是否禁用了 Cookie
- 前后端是否在同源下（开发模式用 8081 走代理就没问题）

### 飞书消息发不出去

`application-feishu.properties` 里默认是占位符：

```properties
feishu.webhook.url=${FEISHU_WEBHOOK_URL:https://open.feishu.cn/open-apis/bot/v2/hook/<your-webhook-id>}
```

**要真发消息**，设置环境变量 `FEISHU_WEBHOOK_URL` 为你自己的机器人 webhook，
或者改配置文件。**不配也能跑** —— 只是通知发不出去，不影响主流程。

### AI 助手没反应

`application-ai.properties`：

```properties
ai.api.url=http://localhost:8000/v1/chat/completions
```

**指向的是本地 8000 端口**。如果你没有本地大模型服务，AI 助手会不可用 —— **不影响其他功能**。

要用真实模型，改成任意 OpenAI 兼容地址，例如：

```properties
ai.api.url=https://api.deepseek.com/chat/completions
ai.api.key=<你的 Key>
ai.api.model=deepseek-chat
```
