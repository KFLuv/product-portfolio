## 这个项目最值得看的三点

### 1️⃣ 我修掉了 4 个"看起来能用、其实没生效"的缺陷 ⭐

| # | 改造前 | 问题本质 |
|---|---|---|
| **1** | 用户信息**写死"杨博全"** | **演示时看不出来** —— 你用自己账号登录确实显示你的名字。换个人登录才发现不对 |
| **2** | 改密码**只比两次输入一致就返回"成功"，一个字都没落库** | **用户以为改成功了，下次登录还是老密码** |
| **3** | AI 对话是**硬编码模板** | 不管问什么都答"第一天参观当地著名景点" |
| **4** | 行程按 `id` 查，**改个 id 就能看别人的** | 权限只做在入口是假的 |

> **这四条的共同点:功能"看起来能用"，其实一句都没生效。**
>
> 这一课后来直接影响了我的另一个项目 —— 我在 FaultDetect 里专门给每条结论加了"**反证条件**"，
> 就是为了防止"看起来成功了"这种情况。

### 2️⃣ 新增「行程本」—— 让 AI 的产出可留存

**课程只要求"聊天问答"。但我判断:聊完就丢的助手，用第二次就要重新问一遍。**

所以加了行程本（保存 / 列表 / 查看 / 删除），并做了**完整的越权防护**：

```java
String sql = "select id, title, content, create_time from trip where id = ? and username = ?";
// ★ 同时限定 username：就算前端伪造 id，也查不到别人的行程
```

**接口设计的两个取舍：**

| 取舍 | 理由 |
|---|---|
| **列表不返回正文** | 正文可能很长，列表页只要标题和时间 —— 减少传输量 |
| **未登录直接拒绝** | 不给匿名用户存数据的可能 |

### 3️⃣ 我写了 471 行的 Agent 接入方案

[`源码/docs/技术提炼.md`](源码/docs/技术提炼.md) 里包含：

- **LLM 调用 ≠ Agent** 的判断标准（分水岭是 **Tools**）
- **四步接入 Agent** 的完整代码骨架
- **8 条踩坑清单** —— 包括"必须设 `MAX_ROUNDS` 防止死循环烧钱""`arguments` 是字符串要二次解析""`tool_call_id` 必须回填否则厂商报 400"

> ⚠️ **诚实说明:这份方案只有文档，代码还没写。** 项目目前仍是"LLM 调用"，不是 Agent。

## 我对技术边界的两个判断

| 判断 | 理由 |
|---|---|
| **不接 Agent（首版）** | 课程范围是 LLM 调用。Agent 方案我写完了，**但没有为了显得完整而写代码** |
| **不接 MCP** | 只有 3 个工具且全在自建库里，**直接写 Java 方法更简单**。工具超过 10 个或要接第三方工具时再上 |

> **不是所有新技术都要往产品里堆** —— 这也是产品判断。

## 我在这个项目上还没做到的

| # | 缺什么 | 影响 |
|---|---|---|
| **1** | **Agent 只有方案，没有代码** | 目前是"LLM 调用"，不是 Agent |
| **2** | **密码明文存储** | 应该加 BCrypt 哈希（课程要求"加密写入"，我做的是简单编码，强度不够） |
| **3** | **数据库凭据硬编码在 Java 里** | 应移到配置文件 |
| **4** | **无连接池、无 ORM** | 每次新建连接，并发上来会成瓶颈 |
| **5** | **无多轮上下文** | 一问一答，不记得上一句（Memory 只设计了方案） |
| **6** | **无单元测试** | 全靠手工点页面验证 |
| **7** | **`webapp/` 下有旧版残留** | 还硬编码 `localhost:8081`，是改造前痕迹 |
| **8** | **端口与课程要求不一致** | 课程要求 8081，实际跑 8078 |
